# Сбор через второй сервер (SSH-туннель)

Эта инструкция — как сделать так, чтобы Telegram-бот **собирал объявления по ссылке
одновременно со слежением за новыми**, и ни то ни другое не тормозило.

Обозначения в командах:

| Обозначение | Что подставить |
|---|---|
| `СЕРВЕР_БОТА` | адрес сервера, где работает бот (`avito.py bot`) |
| `ВТОРОЙ_СЕРВЕР` | адрес любого другого вашего сервера с Linux и SSH |

Все команды выполняются от `root`. Где выполнять — написано перед каждым шагом:
**на Mac**, **на сервере бота** или **на втором сервере**.

---

## 1. Зачем это нужно

Авито ограничивает число запросов **с одного IP-адреса**: примерно один запрос в 30 секунд
(~120 в час). Если чаще — капча, потом блокировка адреса.

У бота две задачи, и обе ходят к Авито:

- **слежение** — раз в минуту смотрит первую страницу каждого отслеживаемого поиска;
- **сбор** — проходит все страницы поиска (30–50 штук) и делает таблицу.

С одного адреса они делят один лимит и мешают друг другу. Решение — дать сбору **свой адрес**:
бот на сервере открывает SSH-туннель ко второму серверу, и запросы сбора выходят в интернет
уже оттуда.

```
                       ┌──────────── слежение ─────────────► avito.ru   (IP сервера бота)
 Telegram ◄──► бот ────┤
   (СЕРВЕР_БОТА)       └── сбор ─► 127.0.0.1:1080 ═══SSH═══► ВТОРОЙ_СЕРВЕР ──► avito.ru   (IP второго сервера)
```

Туннель — это обычная команда `ssh -D`: она поднимает на сервере бота локальный
SOCKS-прокси `127.0.0.1:1080`, а всё, что через него идёт, второй сервер отправляет дальше
от своего имени. На втором сервере **ничего не устанавливается** — нужен только SSH,
который там уже есть.

Если туннель упадёт или Авито заблокирует адрес второго сервера, бот сам напишет об этом
в чат и продолжит сбор со своего адреса (общим темпом со слежением, чтобы не перегрузить его).
Через 30 минут он снова попробует второй сервер.

---

## 2. Какой сервер выбрать вторым

- **Не тот, через который идёт ваш VPN.** Если Авито заблокирует адрес, сайт перестанет
  открываться у вас через VPN.
- **Не тот, который Авито уже блокировал.**
- Побольше **свободного процессора**: туннель шифрует трафик. Памяти ему нужно 5–10 МБ,
  трафика — около 100 МБ в час.

Сравнить серверы (**на Mac**, по очереди для каждого):

```bash
ssh root@ВТОРОЙ_СЕРВЕР 'nproc; cat /proc/loadavg; free -m | sed -n 2p'
```

Смотрите на первое число в строке `loadavg` (средняя загрузка за минуту): чем оно меньше
числа ядер (`nproc`), тем свободнее процессор. Например, `0.5` при одном ядре — половина
свободна, `1.00` при одном ядре — занят полностью.

Проверить, что на втором сервере разрешены туннели (**на Mac**):

```bash
ssh root@ВТОРОЙ_СЕРВЕР 'sshd -T | grep -i allowtcpforwarding'
```

Должно быть `allowtcpforwarding yes` (это значение по умолчанию). Если `no` — выберите
другой сервер или поменяйте `AllowTcpForwarding` в `/etc/ssh/sshd_config` второго сервера
и выполните там `systemctl reload ssh`.

## 3. Ключ для туннеля

Туннель поднимает сам сервер бота, поэтому ему нужен **свой** SSH-ключ ко второму серверу.
Делаем отдельный ключ только для этого и ограничиваем его так, чтобы им можно было **только**
держать туннель.

### 3.1. Создать ключ (на сервере бота)

```bash
ssh root@СЕРВЕР_БОТА
ssh-keygen -t ed25519 -N "" -C avito-bot-tunnel -f /root/.ssh/avito_tunnel
cat /root/.ssh/avito_tunnel.pub
```

Последняя команда выведет строку вида
`ssh-ed25519 AAAAC3Nza...длинная строка... avito-bot-tunnel` — это **открытая** часть ключа,
её не страшно показывать. Скопируйте её целиком.

Закрытая часть (`/root/.ssh/avito_tunnel` без `.pub`) остаётся на сервере бота и никуда
не копируется.

### 3.2. Разрешить ключ на втором сервере (на Mac)

Подставьте скопированную строку вместо `ОТКРЫТЫЙ_КЛЮЧ`:

```bash
ssh root@ВТОРОЙ_СЕРВЕР 'echo "restrict,port-forwarding,command=\"/bin/false\" ОТКРЫТЫЙ_КЛЮЧ" >> ~/.ssh/authorized_keys'
```

Что значат опции перед ключом:

| Опция | Что делает |
|---|---|
| `restrict` | запрещает всё: консоль, проброс портов, агент, X11 |
| `port-forwarding` | разрешает обратно только проброс — то, что нужно туннелю |
| `command="/bin/false"` | любая команда этим ключом сразу завершается, ничего не выполнив |

> ⚠ **Не пропускайте `command="/bin/false"`.** Одна `restrict` запрещает вход в консоль,
> но **не запрещает выполнять команды**: с ключом без этой опции сервер бота может
> запустить на втором сервере любую команду от root. Туннелю команды не нужны — он
> запускается с `-N` («без команды»), поэтому ограничение ему не мешает.

Проверить, что строка на месте:

```bash
ssh root@ВТОРОЙ_СЕРВЕР 'grep avito-bot-tunnel ~/.ssh/authorized_keys'
```

Если вы уже добавили ключ **без** `command="/bin/false"`, допишите ограничение так:

```bash
ssh root@ВТОРОЙ_СЕРВЕР 'sed -i "/avito-bot-tunnel/s/^restrict,port-forwarding /restrict,port-forwarding,command=\"\/bin\/false\" /" ~/.ssh/authorized_keys && grep avito-bot-tunnel ~/.ssh/authorized_keys'
```

## 4. Проверить туннель вручную (на сервере бота)

Поднимем временный туннель на запасном порту 1081, чтобы не мешать постоянному:

```bash
ssh -f -N -D 127.0.0.1:1081 -i /root/.ssh/avito_tunnel \
    -o BatchMode=yes -o ExitOnForwardFailure=yes -o StrictHostKeyChecking=accept-new \
    root@ВТОРОЙ_СЕРВЕР && echo "туннель поднят"
```

- `-f` — уйти в фон после подключения;
- `-N` — не выполнять команд, только туннель;
- `-D 127.0.0.1:1081` — SOCKS-прокси на этом порту, доступный только с самого сервера;
- `StrictHostKeyChecking=accept-new` — при первом подключении запомнить ключ второго сервера
  (при следующих — сверять с ним).

С каким адресом выходит трафик через туннель:

```bash
curl -s --socks5-hostname 127.0.0.1:1081 https://ifconfig.me; echo
```

Должен быть адрес **второго** сервера (может быть IPv6 — это нормально). Если выводится
адрес сервера бота или ничего — туннель не работает, см. раздел 9.

Проверить, что Авито через туннель отдаёт объявления (обычный `curl` для этого не годится:
Авито всем отвечает кодом 439/429, а проходит проверку только настоящий клиент бота).
Подставьте имя любого своего поиска вместо `ИМЯ_ПОИСКА` (список: `ls /opt/avito-parser/searches`):

```bash
cd /opt/avito-parser
mkdir -p /tmp/avitotest && cp searches/ИМЯ_ПОИСКА.json /tmp/avitotest/
.venv/bin/python - <<'EOF' 2>&1 | grep -v WARNING
from pathlib import Path
import avito, avito_client
avito.SEARCHES_DIR = Path("/tmp/avitotest"); avito.DATA_DIR = Path("/tmp/avitotest/data")
s = avito.load_search("ИМЯ_ПОИСКА")
c = avito_client.CalmClient(delay=8, log=avito.say, proxy="socks5h://127.0.0.1:1081")
for n in (1, 2, 3):
    p = c.page(catalog_url=s.catalog_url, params=s.request_params, number=n)
    print("стр.", n, "объявлений", len(p.items))
EOF
rm -rf /tmp/avitotest
```

Хороший результат — три строки по ~50 объявлений. Данные проверка пишет во временную папку,
ваши поиски не трогает.

Убрать временный туннель:

```bash
pkill -f "D 127.0.0.1:1081"
```

## 5. Постоянный туннель как служба (на сервере бота)

Адрес второго сервера — в отдельном файле, чтобы потом менять его одной строкой:

```bash
echo "TUNNEL_HOST=ВТОРОЙ_СЕРВЕР" > /etc/default/avito-tunnel
```

Служба:

```bash
cat > /etc/systemd/system/avito-tunnel.service <<'EOF'
[Unit]
Description=SOCKS tunnel for avito-bot scans (127.0.0.1:1080 -> second server)
After=network-online.target
Wants=network-online.target

[Service]
EnvironmentFile=/etc/default/avito-tunnel
ExecStart=/usr/bin/ssh -N -D 127.0.0.1:1080 -i /root/.ssh/avito_tunnel -o BatchMode=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o StrictHostKeyChecking=accept-new root@${TUNNEL_HOST}
Restart=always
RestartSec=20

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now avito-tunnel
systemctl status avito-tunnel --no-pager
```

Что важно в настройках:

- `ServerAliveInterval=30` + `ServerAliveCountMax=3` — если второй сервер перестал отвечать,
  ssh заметит это примерно за полторы минуты и завершится;
- `Restart=always` + `RestartSec=20` — после этого systemd поднимет туннель заново через 20 секунд,
  и так же после перезагрузки сервера;
- `ExitOnForwardFailure=yes` — если порт 1080 занят, служба сразу упадёт с понятной ошибкой,
  а не будет «работать» без прокси;
- `127.0.0.1` — прокси доступен только самому серверу бота, снаружи к нему не подключиться.

Проверка:

```bash
systemctl is-active avito-tunnel                                  # active
ss -ltnp | grep 1080                                              # ssh слушает 127.0.0.1:1080
curl -s --socks5-hostname 127.0.0.1:1080 https://ifconfig.me; echo   # адрес второго сервера
```

## 6. Включить туннель в боте (на сервере бота)

Боту нужен параметр `--scan-proxy`. Откройте службу бота:

```bash
nano /etc/systemd/system/avito-bot.service
```

1. В строке `ExecStart=` допишите в конец:
   ```
   --scan-proxy socks5h://127.0.0.1:1080
   ```
   Получится, например:
   ```
   ExecStart=/opt/avito-parser/.venv/bin/python avito.py bot --watch-interval 60 --scan-proxy socks5h://127.0.0.1:1080
   ```
   `socks5h` (с буквой **h**) — адрес avito.ru определяет второй сервер, а не сервер бота.
2. В строке `After=` допишите `avito-tunnel.service`, чтобы при загрузке бот стартовал после туннеля:
   ```
   After=network-online.target avito-tunnel.service
   ```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`) и примените:

```bash
systemctl daemon-reload
```

### Перезапуск — только когда бот ничего не собирает

Перезапуск обрывает идущий сбор, а очередь сборов пропадает (собранное не теряется: после
перезапуска «📥 Собрать» продолжит с той же страницы). Посмотрите последние строки журнала
**прямо перед** перезапуском:

```bash
journalctl -u avito-bot -n 5 -o cat --no-pager
```

Если последние строки — `▶ Сбор …` или `стр. N: …` без `✓ Таблица` после них, идёт сбор:
дождитесь таблицы. Потом:

```bash
systemctl restart avito-bot
systemctl is-active avito-bot
```

## 7. Как убедиться, что всё работает

- **В Telegram:** кнопка «ℹ️ Что делаю» пишет
  «Сбор идёт через второй сервер, слежение ему не мешает».
- **Запустите сбор** («📋 Мои поиски» → «📥 Собрать») и смотрите журнал:
  ```bash
  journalctl -u avito-bot -f -o cat | grep -v WARNING
  ```
  Страницы сбора (`стр. N: …`) идут примерно раз в 30 секунд, а между ними продолжают
  появляться проверки слежения — независимо друг от друга.
- **Туннель реально используется:** во время сбора
  ```bash
  ss -tnp | grep 1080
  ```
  показывает соединения к `127.0.0.1:1080`.

## 8. Сменить второй сервер

1. На новом втором сервере выполните шаг 3.2 (тот же открытый ключ).
2. На сервере бота:
   ```bash
   echo "TUNNEL_HOST=НОВЫЙ_СЕРВЕР" > /etc/default/avito-tunnel
   systemctl restart avito-tunnel
   curl -s --socks5-hostname 127.0.0.1:1080 https://ifconfig.me; echo
   ```
   Бота перезапускать не нужно: следующий сбор пойдёт через новый адрес.
3. На старом втором сервере уберите ключ (раздел 10).

## 9. Если что-то не работает

Журнал туннеля:

```bash
journalctl -u avito-tunnel -n 30 -o cat --no-pager
```

| Сообщение / симптом | Причина и что делать |
|---|---|
| `Permission denied (publickey)` | Ключ не добавлен на второй сервер или добавлен с ошибкой. Повторите шаг 3.2 и проверьте `grep avito-bot-tunnel ~/.ssh/authorized_keys` на втором сервере. |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | Второй сервер переустановлен, у него новый ключ. Если вы это делали: `ssh-keygen -R ВТОРОЙ_СЕРВЕР` на сервере бота и `systemctl restart avito-tunnel`. **Если не делали — не продолжайте**, это может быть подмена сервера. |
| `bind [127.0.0.1]:1080: Address already in use` | Порт занят (например, старым ручным туннелем). `ss -ltnp \| grep 1080` покажет кем; лишний `ssh` остановите `pkill -f "D 127.0.0.1:1080"` и `systemctl restart avito-tunnel`. |
| `channel ... open failed: administratively prohibited` | На втором сервере запрещены туннели или ключ добавлен без `port-forwarding`. См. разделы 2 и 3.2. |
| `Connection timed out` / `Connection refused` | Второй сервер выключен, недоступен или закрыт порт 22. |
| Бот пишет «⚠ Второй сервер для сбора недоступен (туннель не отвечает)» | Туннель упал. Смотрите журнал туннеля. Бот сам вернётся к нему через 30 минут. |
| Бот пишет «⚠ Второй сервер для сбора недоступен (Авито не пускает через него)» | Авито заблокировал адрес второго сервера. Блокировка обычно снимается через часы или дни; можно сменить второй сервер (раздел 8). |
| «ℹ️ Что делаю» не упоминает второй сервер | Бот запущен без `--scan-proxy`: проверьте `ExecStart` (шаг 6), `systemctl daemon-reload` и перезапуск. |

## 10. Как всё убрать

На сервере бота:

```bash
systemctl disable --now avito-tunnel
rm /etc/systemd/system/avito-tunnel.service /etc/default/avito-tunnel
nano /etc/systemd/system/avito-bot.service   # убрать --scan-proxy ... и avito-tunnel.service из After=
systemctl daemon-reload && systemctl restart avito-bot   # когда бот ничего не собирает
rm /root/.ssh/avito_tunnel /root/.ssh/avito_tunnel.pub
```

На Mac — убрать ключ со второго сервера:

```bash
ssh root@ВТОРОЙ_СЕРВЕР 'sed -i "/avito-bot-tunnel/d" ~/.ssh/authorized_keys'
```

Без `--scan-proxy` бот работает как раньше: сбор и слежение идут с одного адреса
и делят его лимит.

## Запуск на Mac вместо сервера

Тот же приём работает и локально. В одном окне терминала:

```bash
ssh -N -D 127.0.0.1:1080 root@ВТОРОЙ_СЕРВЕР
```

(оставьте окно открытым — пока оно открыто, туннель работает), во втором:

```bash
uv run python avito.py bot --scan-proxy socks5h://127.0.0.1:1080
```

Не запускайте бота на Mac, пока он работает на сервере: два бота с одним токеном Telegram
мешают друг другу.
